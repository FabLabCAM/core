# Validation de 0.7.1 — issue #24

État : préparation des PR, aucune release 0.7.1 publiée à ce stade.
Vérifications locales les 4–5 novembre 2026 sur macOS 26.2 Apple Silicon,
Rust 1.99.1. Tests de calcul et de bureau, pas qualification d'une CNC.

## Reproduction et correction

Le DXF joint à l'issue contient vingt formes. Un probe local de chaque offset
isole la forme #12 : lettre E, treize sommets avec fermeture explicite répétée.
Les offsets ±1,5 mm reproduisent en release `Option::unwrap()` à
`cavalier_contours 0.3.0/pline_offset.rs:714:75`, comme le journal utilisateur.
En debug, l'assertion préalable du noyau signale les positions répétées.
Le volume de sommets des autres lettres n'est donc pas la cause de ce cas.

Le test synthétique `closed_offset_regression` échoue avant correction, puis
passe en debug et release. Il compare aire/périmètre et coordonnées finies aux
contours propres, dans les deux sens, sans modifier l'entrée. Les tests de
positions répétées couvrent aussi une ligne ouverte et les bulges d'arcs.

Sur le DXF original, fraise 3 mm et réglages initiaux :

| Sélection / côté | Résultat |
|---|---|
| 19 formes, extérieur | 32 415 mouvements |
| 19 formes, intérieur | 23 227 mouvements |
| 19 formes, sur le trait | 26 629 mouvements |
| Vingt formes testées séparément, cadre compris | Calculs réussis |
| Sauvegarde/rechargement, annulation | Dessin intact, G-code identique au rechargement |

Le test `profile_crash` reconstruit dix-neuf E synthétiques via DXF et protège
historique, persistance, côtés et refus d'export après échec de recalcul.
Le fichier utilisateur et ses métadonnées ne sont pas ajoutés au dépôt.

## Diagnostic et interface

- Préférences réelles testées avec `docs/examples/plaque.rhai` : niveau Détaillé,
  traces complètes, persistance dans un dossier isolé, armement/désarmement,
  limite souple revenue à zéro, export texte de 851 octets vérifié.
- Après relance avec le DXF original et sélection 2–20, le clic **Profil** crée
  l'opération et affiche **OK : 32415 mouvements**. L'interface reste utilisable.
- La capture du guide provient du binaire local 0.7.1, avec le projet synthétique
  de la plaque. Elle ne provient pas d'un paquet publié.
- Tests de service : réglages invalides, dossier invalide, filtrage, rotation,
  instances simultanées, événement excessif, exclusion des cores/projets,
  deux paniques successives, pile sans variable d'environnement, repli stderr.
- Sous-processus signé pour diagnostic : SIGABRT après rapport, refus si limite
  dure nulle, restauration de la limite après désarmement.
- Panne Rust contrôlée : core de **5 709 119 504 octets**, ouvert dans LLDB ;
  les frames `panic_report`, `panic_child` et leurs lignes source sont présentes.
  Le rapport texte est écrit avant l'arrêt. Ce core de test a été supprimé après
  vérification, jamais exporté ni ajouté au dépôt.

Les tests core nécessitant des préconditions système passent leur partie capture
uniquement sur un binaire signé pour diagnostic ; la suite standard conserve
la signature normale. Les paquets normaux affichent la raison du refus.

## Commandes

```sh
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --release -p fablabcam-geom --test closed_offset_regression
python3.12 packaging/diagnostic_macos.py
```

La suite locale compte **403 tests**. Les commandes workspace, Clippy strict et
la régression géométrique en release sont vérifiées après les derniers ajustements. La CI native des autres OS, les six paquets, leur
installation et la publication restent à contrôler dans les PR. La compilation
optimisée de diagnostic a réussi, avec vérification de signature et UUID identiques
entre le binaire et le dSYM. Le guide passe MkDocs strict et le contrôle de ses
37 pages ; son rendu a aussi été inspecté.

## Limites

Le rattrapage couvre les paniques Rust déroulables du calcul d'opération ; pas
SIGKILL, l'épuisement mémoire, un blocage natif ou toutes les erreurs FFI. Le mode
core arme un arrêt volontaire même pour une panique normalement récupérable.
La limite virtuelle de 1 Tio et les 10 Gio libres exigés ne garantissent pas une
limite disque stricte ni l'acceptation finale de la capture par macOS.
Les autres systèmes disposent du rapport texte, pas d'un backend core intégré.
